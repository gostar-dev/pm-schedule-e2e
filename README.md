# PM 착수일 역산 계산기 E2E 테스트

출시일과 단계별 작업량을 넣으면 공휴일과 주말을 빼고 단계별 착수일을 거꾸로 계산하는 웹 계산기를 Playwright와 TypeScript로 테스트하는 프로젝트입니다.

- 테스트 대상: `app/index.html` (PM 착수일 역산 계산기, 개인 프로젝트)
- 테스트: 6개 파일, 19개 시나리오
- 브라우저: Chromium, Firefox, WebKit, 모바일 Chrome(Pixel 7)
- CI: GitHub Actions에서 푸시마다 브라우저별로 실행, 실패하면 리포트와 트레이스를 남김

## 실행

```bash
npm ci
npx playwright install            # 처음 한 번, 브라우저 설치
npm test                          # 전체 브라우저
npm run test:chromium             # Chromium만
npm run report                    # HTML 리포트 열기
```

## 무엇을 체크하나

| 파일 | 체크하는 것 |
|---|---|
| `calc.spec.ts` | 기준 착수일과 남은 근무일, 설 연휴 건너뛰기, 배포일 변경, 이미 늦은 일정, 공휴일 목록이 없는 해 경고 |
| `items.spec.ts` | 콘텐츠 추가와 삭제, 규모 변경에 따른 기간과 착수일 변화 |
| `settings.spec.ts` | 인원 0 입력 차단, 단계 추가, 마지막 순차 단계 보호, 기본값 되돌리기 |
| `persistence.spec.ts` | 새로고침 후 유지, JSON 내보내기와 불러오기 왕복, 형식이 다른 JSON 거부 |
| `data.spec.ts` | 필수 열이 없는 CSV 안내, EUC-KR 한글 CSV 열 자동 인식, 샘플 데이터 보정 후 안전 80% 기준 |
| `responsive.spec.ts` | 휴대폰 폭에서 결론과 일정표 표시, 가로 넘침 없음 |

자세한 범위와 우선순위는 [docs/TEST_PLAN.md](docs/TEST_PLAN.md)에 있습니다.

## 설계에서 정한 것

1. **시계 고정:** 계산기는 오늘을 기준일로 씁니다. 그대로 두면 실행하는 날마다 기대값이 바뀌므로 `page.clock.setFixedTime`으로 2026-11-24 10:00(서울)에 고정했습니다. 시간대와 언어도 `Asia/Seoul`, `ko-KR`로 맞췄습니다.
2. **페이지 객체:** 선택자와 화면 동작은 `tests/pages/CalculatorPage.ts` 한곳에 모았습니다. 테스트 파일에는 업무 문장만 남기고, 화면 구조가 바뀌면 이 파일만 고칩니다.
3. **자바스크립트 오류 자동 실패:** 공통 픽스처(`tests/fixtures/base.ts`)가 `pageerror`를 모아, 화면이 정상으로 보여도 오류가 나면 테스트를 실패시킵니다.
4. **고정 대기 없음:** `waitForTimeout`을 쓰지 않고 `expect`의 자동 재시도와 `expect.poll`로 기다립니다.
5. **실패 분석:** 실패하면 스크린샷과 트레이스를 남기고, CI에서는 브라우저별 리포트를 올립니다.

## 테스트가 실제로 결함을 잡는지 확인

앱 코드에 일부러 결함을 넣고 테스트가 실패하는지 확인했습니다. 네 가지 모두 잡혔습니다.

| 넣은 결함 | 실패한 테스트 |
|---|---|
| 2027년 설 연휴 이틀을 공휴일 목록에서 삭제 | `calc.spec.ts` 2건 |
| 인원 0 입력 차단 코드 삭제 | `settings.spec.ts` 1건 |
| 불러온 JSON 형식 검사 삭제 | `persistence.spec.ts` 1건 |
| 브라우저 저장 끄기 | `persistence.spec.ts` 2건 |

만드는 중에 엉뚱한 이유로 통과하던 테스트도 찾았습니다. 콘텐츠 삭제 확인을 일정표 전체 글자에 `2.`가 없는지로 했더니 날짜(27.2.2)와 겹쳐 실패했고, 추가 확인의 `3.`은 `3.0MD`와 겹쳐 결함이 있어도 통과할 수 있었습니다. 지금은 일정표 첫 칸의 콘텐츠 번호만 읽어 비교합니다.

## 실행 결과 (로컬)

- Chromium 19개 통과, 같은 테스트 3회 반복 57개 모두 통과
- 모바일 Chrome 1개 통과
- Firefox와 WebKit은 로컬 환경에 브라우저가 없어 GitHub Actions에서 실행합니다

## 만든 방식

테스트 범위, 우선순위, 기대값과 결함 주입 확인 항목은 제가 정했고, 코드는 AI 코딩 도구(Claude)가 작성했습니다. 결과는 제가 직접 실행해 확인했습니다.
