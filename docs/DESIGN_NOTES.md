# 설계 메모 (면접 준비용)

**왜 이 계산기를 대상으로 골랐나**
직접 만든 도구라 기능과 기대값을 정확히 알고, 날짜 계산, 공휴일, 입력 검증, 저장처럼 테스트할 로직이 실제로 있기 때문입니다.

**날짜가 바뀌면 결과가 달라지는 문제는 어떻게 했나**
계산기는 오늘을 기준일로 씁니다. Playwright의 `page.clock.setFixedTime`으로 시계를 2026-11-24에 고정해 언제 돌려도 같은 결과가 나오게 했습니다.

**선택자는 어떻게 관리하나**
페이지 객체 한 파일에 모았습니다. 테스트에는 배포일을 바꾼다, 콘텐츠를 지운다 같은 동작만 남깁니다.

**기다림은 어떻게 처리했나**
고정 시간 대기는 쓰지 않았습니다. `expect`가 조건이 맞을 때까지 다시 확인하는 기능과 `expect.poll`을 씁니다. 같은 테스트를 3번 반복해 57개 모두 통과하는 것으로 흔들림이 없는지 확인했습니다.

**테스트가 진짜 결함을 잡는지 어떻게 아나**
앱에 일부러 결함 네 가지를 넣고 테스트가 실패하는지 봤습니다. 공휴일 삭제, 인원 0 허용, JSON 검사 삭제, 저장 끄기를 모두 잡았습니다.

**만들면서 겪은 문제**
일정표 전체 글자에서 `2.`를 찾지 않는 방식으로 삭제를 확인했더니 날짜 27.2.2와 겹쳐 실패했습니다. 같은 방식의 추가 확인은 `3.0MD`와 겹쳐 결함이 있어도 통과할 수 있었습니다. 엉뚱한 이유로 통과하는 테스트가 더 위험하다고 보고, 첫 칸의 콘텐츠 번호만 비교하도록 바꿨습니다.

**실패하면 무엇을 보나**
스크린샷, 트레이스, CI의 브라우저별 HTML 리포트를 봅니다. 트레이스로 실패 직전 화면과 클릭 순서를 다시 볼 수 있습니다.

**역할**
범위, 우선순위, 기대값, 결함 주입 항목은 제가 정했고 코드는 Claude가 작성했습니다. 실행과 결과 확인은 제가 했습니다.
